# Sisyphus 项目级行为规则

> 继承全局规则（`~/.config/opencode/.sisyphus/SYSTEM_BEHAVIOR.md`），以下为项目特有补充。

---

## 0. 语言规则（优先级最高）

1. **思考语言**：所有内部思考、分析、推理过程使用中文
2. **输出语言**：所有给用户的回复使用中文
3. **代码/日志引用**：代码内容、错误消息保持原文（不翻译），上下文说明用中文

---

## 1. 主线程非阻塞原则

1. **主对话线程**不做任何阻塞性思考或工作
2. **60 秒阈值**：任何任务预计超过 60 秒，必须立即考虑交割给子线程（`task(run_in_background=true, ...)`）
3. **响应优先**：主线程始终保持可响应状态，随时可以处理用户新指令
4. **后台任务**：子线程运行期间，主线程可以处理其他独立工作或等待指令

---

## 2. Delegation 决策规则

| 复杂度 | 判定标准 | 策略 |
|--------|----------|------|
| 简单 | 单文件改/读，或单步操作 | **直接做**，不做 delegate |
| 中 | 2-3 个文件改动，需 build 验证 | **直接做 + build 验证** |
| 高 | 架构级/跨模块/需要深度分析 | delegate `deep` 类别 |
| 机械重复 | 批量修改 N 个同类文件 | 写脚本或用工具批量操作，不做 agent 逐个处理 |

**容错机制**：
- Delegate 超时 3 分钟未返回 → 切回直接做
- Delegate 失败 2 次 → 切回直接做，不再重试代理

---

## 3. 文件搜索策略（硬性禁用规则）

**⚠️ 全局禁用以下工具：**
- **Glob 工具** — 永不使用（Windows 上不排除 node_modules，搜索 4000+ .ts 文件导致卡死）
- **Grep 工具** — 永不使用（同样扫 node_modules）

**允许的工具（按优先级）：**
1. **`Read` 工具** — 知道文件路径时直接读取
2. **`Bash` 工具**（`Get-ChildItem` + `Select-String`，必须指定具体路径，禁止无限制递归）
3. **`Ast-grep` 工具** — 仅在已知的小目录范围内使用
4. **`explore` 子代理** — 作为最后手段，路径范围必须明确限定

**禁止行为：**
- 不带路径限制的 `glob("**/*.ts")` — ❌
- 不带路径限制的 `grep(...)` — ❌

---

## 4. Shell/Build 超时处理

所有 shell 命令统一规则：

1. **超时阈值**: 3 分钟
2. 超过 3 分钟未返回 → 视为后台运行，**不原地等待**
3. 立即切换到其他独立任务继续工作
4. 每 **2 分钟**检查一次该 shell 操作的结果
5. Build 产物检查：看 `bin/Debug/` 目录是否存在 `.dll`，而非重新编译
6. NuGet restore 检查：看 `obj/project.assets.json` 是否存在

---

## 5. 任务完成汇报

每次任务完成后：

1. 确认所有后台任务均已结束（`background_cancel` / 等待系统通知完成）
2. 汇总改动概要（文件、变更内容、编译/测试状态）
3. 列出下一步可选方向（不超过 4 个，附带预估耗时）
4. 等待用户指示，**不自行推进下一步**

### 汇报格式模板

```
## 改动概要

| 区域 | 变更 | 文件数 |
|------|------|--------|

**编译验证**: X errors, X warnings

## 下一步可选方向

| # | 方向 | 预估 |
|---|------|------|
```

---

## 6. 代理可见性与追踪

1. 每个 `task()` 调用**必须包含 `description` 字段**
2. 代理产出丢失时 → 切换到直接验证文件存在性
3. 记录关键 task_id 以便后续恢复

---

## 7. 执行底线（不可违反）

- 禁止类型压制：`as any`、`@ts-ignore`、`@ts-expect-error`
- 禁止空 catch 块
- 禁止删除测试以"通过"
- 禁止在代码不确定时猜测，必须读文件确认
- 禁止提交代码除非用户明确要求
- 禁止在代码中引入 AI 注释签名
- 修复 Bug 时最小改动，绝不附带重构

---

## 8. 项目特定配置

### 8.1 技术栈
- **前端**: Vue 3 + TypeScript + Vite + Playwright
- **后端**: ASP.NET Core 8.0 (C#)
- **数据库**: PostgreSQL
- **测试**: Playwright E2E + xUnit/dotnet test

### 8.2 常用命令
```powershell
# 前端
npm run dev              # 启动开发服务器
npx playwright test      # 运行 E2E 测试

# 后端
dotnet build             # 编译
dotnet test              # 运行测试 (Server.Tests)
dotnet run --project Editor/Server  # 启动 API
```

### 8.3 代码规范
- C#: 遵循 .NET 团队编码约定（PascalCase 公开成员、\_camelCase 私有字段）
- Vue/TS: ESlint + Prettier 规则
- API: RESTful 契约，Swagger/OpenAPI 文档
