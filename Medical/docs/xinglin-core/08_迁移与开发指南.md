# 从 `xinglin` 到 `xinglin-core`：开发与迁移指南

## 1. 引言

本指南旨在为 `kongliuli/xinglin` 项目的开发者提供从旧仓库 (`xinglin`) 到新仓库 (`xinglin-core`) 的开发与迁移策略。我们将重点阐述如何利用 Trae AI 助手及其内置的 `mvvm-wpf-expert` 技能，高效地进行代码重构、功能迁移和新功能开发，确保项目遵循现代 .NET 8 WPF MVVM 最佳实践。

## 2. 仓库概览与核心差异

### 2.1 旧仓库 (`xinglin`)

旧仓库 `xinglin` 包含了三个主要分支，各自承担了不同的职责：

*   **`main` 分支**：主要用于存放项目的高层设计文档和开发计划。
*   **`master` 分支**：包含了 `ReportTemplateEditorDemo` 项目，这是一个功能较为完整的报表模板编辑器，但可能存在较旧的技术栈和冗余文件。
*   **`Main-Demo` 分支**：包含了 `Demo_ReportPrinter` 项目，是当前活跃开发的分支，采用了 .NET 8 和 CommunityToolkit.Mvvm 等较新的技术，并集成了 Trae AI 辅助开发的 `.trae` 技能配置。

### 2.2 新仓库 (`xinglin-core`)

新仓库 `xinglin-core` 是对旧仓库的梳理和重构，旨在提供一个更清晰、更现代、更易于维护的开发基础。其核心结构如下：

*   **`/src` 目录**：存放了从 `Main-Demo` 分支提取并清理后的核心 WPF 项目代码，遵循 .NET 8 和 CommunityToolkit.Mvvm 架构。
*   **`/docs` 目录**：整合了原 `main` 分支下的所有详细设计文档，作为项目的唯一文档源。
*   **`.trae` 目录**：包含了经过专业化整合的 `mvvm-wpf-expert` 技能，为 Trae AI 助手提供统一的开发规范和指导。
*   **`.gitignore` 文件**：配置了标准的 .NET 忽略规则，移除了所有冗余的缓存、临时文件和旧的嵌套目录。

**核心差异总结：**

| 特性           | 旧仓库 (`xinglin`)                               | 新仓库 (`xinglin-core`)                                  |
| :------------- | :----------------------------------------------- | :------------------------------------------------------- |
| **项目结构**   | 分散，多分支承载不同内容，存在冗余和嵌套         | 统一，`src` (代码), `docs` (文档), `.trae` (AI 技能)     |
| **技术栈**     | `master` 可能较旧，`Main-Demo` 采用 .NET 8 MVVM | 统一采用 .NET 8 + CommunityToolkit.Mvvm                  |
| **AI 技能**    | 分散的多个 `.trae/skills`                        | 整合为 `mvvm-wpf-expert` 单一技能，更专业化和集中       |
| **文档管理**   | `main` 分支独立管理文档                          | `docs` 目录统一管理，与代码仓库同步                      |
| **代码清理**   | 存在大量缓存和临时文件                           | 彻底清理，`.gitignore` 规范化                            |

## 3. 迁移策略：利用 Trae AI 助手

迁移过程将主要关注从 `xinglin` 的 `master` 分支中提取可能仍有价值的业务逻辑，并将其重构到 `xinglin-core` 的现代架构中。Trae AI 助手及其 `mvvm-wpf-expert` 技能将在此过程中发挥关键作用。

### 3.1 阶段一：代码提取与初步分析

**目标**：识别 `xinglin/master` 中需要迁移的业务逻辑代码（例如，特定的报表生成算法、数据处理逻辑），并将其复制到 `xinglin-core` 的临时目录中进行初步分析。

**Trae AI 提示词示例**：

> 
```text
请分析旧仓库 `xinglin` 的 `master` 分支中 `ReportTemplateEditorDemo` 项目的以下文件：
- `ReportTemplateEditorDemo/ReportTemplateEditor.Designer/Services/ReportGeneratorService.cs`
- `ReportTemplateEditorDemo/ReportTemplateEditor.App/Services/PrintService.cs`

识别其中与报表生成核心逻辑、数据处理相关的代码片段，并将其复制到 `/home/ubuntu/temp_migration/` 目录下。请勿复制任何 UI 或旧版 MVVM 相关的代码。
```

### 3.2 阶段二：代码重构与适配

**目标**：将提取出的旧代码重构为符合 `xinglin-core` 规范的 .NET 8 MVVM 模式，并适配 `CommunityToolkit.Mvvm` 的 Source Generators。

**Trae AI 提示词示例**：

```text
我正在将旧仓库 `xinglin` 中的代码迁移到 `xinglin-core`。请根据 `mvvm-wpf-expert` 技能的规范，将 `/home/ubuntu/temp_migration/ReportGeneratorService.cs` 中的核心报表生成逻辑重构为一个新的服务 `ReportGenerationService.cs`，并将其放置在 `xinglin-core/src/Services/` 目录下。

重构要求：
1.  使用依赖注入 (DI) 模式，如果需要任何依赖，请确保它们通过构造函数注入。
2.  移除所有旧的 UI 耦合代码。
3.  确保代码符合 .NET 8 异步编程的最佳实践。
4.  如果存在任何旧的 ADO.NET 数据库访问代码，请将其替换为现代的 ORM 方式（例如，如果项目引入了 SqlSugar，则使用 SqlSugar）。
```

```text
请根据 `mvvm-wpf-expert` 技能的规范，为 `xinglin-core/src/ViewModels/` 目录下的 `MainViewModel.cs` 添加一个异步命令 `GenerateReportCommand`。

该命令应调用 `ReportGenerationService` 中的 `GenerateReport` 方法，并具备以下特性：
1.  使用 `[RelayCommand(IncludeCancelCommand = true)]` 特性，支持任务取消。
2.  在命令执行期间，设置 `IsBusy` 属性为 `true`，并在完成后设置为 `false`。
3.  处理可能发生的异常，并更新 `ErrorMessage` 属性。
4.  如果 `ReportGenerationService` 支持进度报告，请集成 `IProgress<T>`。
```

### 3.3 阶段三：新功能开发

**目标**：基于 `xinglin-core` 的新架构和 `mvvm-wpf-expert` 技能，开发新的功能模块，例如“多源数据接入”。

**Trae AI 提示词示例**：

```text
我需要在 `xinglin-core` 项目中实现“多源数据接入”功能。请根据 `mvvm-wpf-expert` 技能的规范，为该功能设计以下组件：

1.  **数据源配置 ViewModel**：`DataSourceConfigViewModel.cs`，用于管理不同数据源（HIS、身份证读卡器、API）的配置信息。该 ViewModel 应包含 `ObservableCollection<DataSource>` 属性，并支持添加、编辑、删除数据源的 `RelayCommand`。
2.  **数据源服务接口与实现**：`IDataSourceService.cs` 和 `DataSourceService.cs`，负责实际的数据源连接和数据获取逻辑。该服务应通过 DI 注册为 `Singleton` 或 `Scoped`。
3.  **XAML UI 布局**：为 `DataSourceConfigView.xaml` 提供一个基本的布局，用于展示数据源列表和配置表单。请使用 `DataTemplate` 和 `ControlTemplate` 来美化界面。

请确保所有生成的代码都符合 .NET 8 MVVM 模式，并利用 `CommunityToolkit.Mvvm` 的 Source Generators。
```

## 4. 验证与测试

在每个迁移或开发阶段完成后，都应进行充分的验证和测试。Trae AI 助手可以协助生成单元测试或集成测试的骨架。

**Trae AI 提示词示例**：

```text
请为 `xinglin-core/src/Services/ReportGenerationService.cs` 生成单元测试的骨架。测试应覆盖以下场景：
1.  成功生成报表。
2.  处理无效输入。
3.  在取消操作时正确停止。

请使用 `xUnit` 和 `Moq` 框架。
```

## 5. 持续集成与部署

`xinglin-core` 仓库的标准化结构为持续集成/持续部署 (CI/CD) 流程奠定了基础。建议配置 GitHub Actions 或其他 CI/CD 工具，在每次代码提交后自动构建、测试和部署应用程序。

## 6. 总结

通过遵循本指南，并充分利用 Trae AI 助手及其 `mvvm-wpf-expert` 技能，您将能够高效、规范地完成 `xinglin` 项目的迁移，并在此基础上持续迭代和开发新功能。这将确保您的项目始终保持在现代 .NET WPF 开发的前沿，并拥有清晰、可维护的代码库。
